# CarbonLens 系統架構

## 案件如何運作

分析師從內建 Synthetic Data 選擇基金，或上傳基金、持股與基準 CSV。表單顯示解析錯誤及原始宣稱，使用者可編輯文字後建立案件。每個案件鎖定一檔基金、一個報告年度與一個市場基準，保留送出時的資料快照。上傳多檔基金時，先選擇要分析的基金；同一基金可建立不同案件。

| 元件 | 責任 |
| --- | --- |
| Streamlit 與 Plotly | 顯示 Dashboard、表單、執行進度、警示、摘要、證據與覆核介面。圖表讀取案件的實際資料與運算結果。 |
| Pandas 與資料驗證模組 | 解析 CSV、保留來源與列號、驗證欄位、鍵值、年度、範疇、權重、單位與可比較性，回傳結構化問題及覆蓋率。 |
| 單一 Agent | 協調擷取、驗證、計算與結果組裝，依案件狀態呼叫工具或等待補件與覆核。分支由 Python 依狀態執行。 |
| OpenAI Python SDK | 透過 Responses API 的 Structured Outputs 擷取宣稱，並由 Python 檢查輸出欄位、原文證據與語意限制。模型名稱來自環境變數。 [OpenAI 官方文件](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses) |
| Python 金融計算模組 | 計算逐筆持股貢獻、WACI、相對降低比例，依未四捨五入的數值判定。函式可獨立於 UI、模型與資料庫測試。 |
| 案件儲存模組 | 本機以 SQLite 儲存資料快照、分析執行、步驟紀錄及覆核。透過一致的讀寫介面，為日後部署接持久化資料庫保留替換空間。 |
| 報告匯出模組 | 從指定分析版本匯出結果、覆核與來源索引。CSV 為基本交付，PDF 視繁體中文字型與版面驗證結果納入。 |

資料路徑為 **表單／CSV → 案件快照 → Agent → 擷取與驗證 → Python 計算與判定 → 儲存 → Dashboard／覆核／匯出**。模型的輸入限於原始宣稱與擷取指示。應用程式用案件快照比對基準、年度與證據，並保留驗證時採用的公式版本。合成資料的 `claimed_reduction_pct` 僅用於驗收。

## 網站與分析結果

- **Dashboard** 顯示已產出判定的去重基金數、依最新執行版本統計的三種案件判定，以及待覆核案件數。概覽同時列出案件 ID、基金、年度、分析與覆核狀態。執行失敗與待確認可在案件清單查閱。
- **案件表單** 支援選擇示範基金、上傳 CSV、輸入原文與建立案件。欄位錯誤提示檔案、列號及修正方式。示範資料在畫面與匯出標示 Synthetic Data。
- **分析頁** 顯示 Agent 步驟、擷取欄位、宣稱降低比例、兩組 WACI、實際降低比例、資料覆蓋率與問題清單。用可追溯的原文、持股、基準和公式呈現摘要。
- **分析圖表** 顯示兩組 WACI、宣稱與實際降低比例、產業權重、企業加權碳強度貢獻。缺少可比較的數值時顯示原因。持股權重有效時仍可顯示產業分布。個別缺漏值保留空白。
- **覆核與匯出** 支援確認、修正擷取欄位和退回重跑。修正後重新驗證、運算並產生新版本。保留原值、修正值、狀態、意見及時間。匯出檔使用 `CarbonLens_<case_id>_<run_id>.csv`，納入分析與覆核狀態，並處理試算表可能將使用者輸入誤讀為公式的情況。

主要介面使用繁體中文，保留 WACI、Scope 1 + Scope 2 等必要術語。Phase 3 將使用深森林綠 `#123C35`、薄荷綠 `#A6E4C6`、米白 `#F7F8F5` 與深灰綠 `#202B28`，設計放大鏡與碳排曲線的品牌標誌，檢查桌面及窄螢幕的閱讀與操作。

## 儲存與操作邊界

| 紀錄 | 內容 |
| --- | --- |
| 案件及輸入快照 | 案件 ID、基金與原文、持股與基準列、資料來源與建立時間 |
| 分析執行 | 執行 ID、輸入快照、版本、擷取來源、公式及結果、問題與證據引用 |
| 步驟紀錄 | 執行 ID、步驟、時間、狀態、錯誤類型與可用的 API 請求識別碼 |
| 覆核紀錄 | 案件與執行 ID、欄位原值及新值、動作、意見與時間 |
| 報告快照 | 固定分析與覆核版本，供後續重現匯出內容 |

開始執行時先登記執行 ID。模型呼叫在資料庫交易之外完成，最後將分析結果與案件最新版本一起提交。覆核動作帶入使用者看到的執行 ID，若版本已變更則提示重新載入，避免兩個瀏覽器視窗覆寫彼此的決策。每次明確重跑產生新執行 ID。

本機憑證由 `.env` 讀取，公開版由部署平台 Secrets 提供。Mock Mode 要主動啟用，並在執行及匯出中標示。真實模式遇到憑證缺漏、逾時、限流或模型無法回傳可驗證的結果時，保留執行狀態並提示處理方式。公開展示先驗證登入與用量限制，再開放真實模型呼叫。長期保存採可持久化的資料庫；使用暫存 SQLite 的展示環境標示保存期限與重啟風險。

## 開發順序

| 階段 | 交付 | 驗證方式 |
| --- | --- | --- |
| 1 | 架構、欄位、計算規則、Agent 流程及驗收設計 | 核對需求、文件連結與三檔設計案例的手算結果 |
| 2 | 合成 CSV、資料驗證、WACI 函式與單元測試 | 用 pytest 比對標準答案，檢查缺漏與邊界 |
| 3 | Streamlit 表單、Dashboard、分析畫面與圖表，以人工輸入且可核對的宣稱欄位先串接 Phase 2 的計算 | 開啟本機網站，輸入三檔示範基金與一組錯誤 CSV |
| 4 | 真實 OpenAI 擷取、狀態分支、執行記錄與明確的 Mock Mode | 用真實 API 執行至少一則宣稱，另驗證無憑證、逾時及待人工確認分支 |
| 5 | 人工覆核、SQLite、案件版本與報告 | 修改擷取、退回重跑、核對舊版證據與下載內容，重啟後讀回本機紀錄 |
| 6 | 至少 20 個獨立案例的驗收、模型與人工基線評估、公開部署 | 保存實測與未達標原因；具備帳號及部署設定後，以公開網址執行功能驗證 |

每一階段都先向使用者交付可查閱的結果及驗證方式，確認後進入下一階段。
